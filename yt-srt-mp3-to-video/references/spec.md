# SRT 旁白驱动的暗色示意动画设计规范（v2）

> v1 的需求边界与设计方法已由用户确认。v2 在此基础上，吸收了对 15 支参考视频的逐帧分析：共抽取 540 段暗色示意动画，全部经用户确认保留。新增内容集中在第 4 节（组件与状态语言）、第 6 节（语义到画面的对照库）、第 7 节（动画手法与节奏）和第 9 节（新增参考图）。
>
> 本文仍是编写 skill 的依据，不是 skill 本身。逐段标注见同目录的 `library.md`（原始抽帧拼图在用户电脑 `/Users/matt/Desktop/YT/z-分析竞品/ai-labs/帧分析/vNN/sheets/`），下文用 `vNN-ID` 指代具体段落（如 `v01-I` 表示视频 01 的 I 段），可在 library.md 中查到该段的画面与动画描述。

## 1. 核心目标

用户会提供不同题材的 SRT。设计者需要完整理解旁白，沿用参考图的视觉语言，为每段内容重新设计示意画面和动画，让画面随旁白同步表达含义。

**旁白讲到什么事情，画面就把这件事情如何发生、如何变化、产生什么结果表现出来。**

> “每个 srt 的内容可能都不相同，但是我希望你使用这些图片的设计风格，来设计旁白对应的画面，不需要有真实的画面，就要这些图片的设计风格来设计画面就行。也就是说，旁白在讲，画面上用这种图片来同步表达旁白的意思，而不是画面上是旁白的文字。”

核心能力：**理解语义 → 找到可视化表达 → 设计画面 → 设计状态变化 → 对齐旁白时间。**

## 2. 边界

### 必须做到

- 以第 9 节的参考图（v1 六组 + v2 新增二十组）为视觉基准。
- 统一暗色、克制、简化的界面式图形语言。
- 每次根据新 SRT 原创构图、对象和动作。
- 用形状、卡片、图标、连接关系、空间位置与状态变化表达含义。
- 动画与旁白的语义发展同步；关键结果不能脱离旁白过早出现。
- 画面可以包含必要的短标签、名称、数字与状态词。
- 全片保持一致的配色、组件样式、运动逻辑与信息层级。

### 属于风格范围、可以使用（v2 经用户确认）

- **风格化终端**：干净的暗色窗口，逐行打字、状态点、删除线，文字只保留两三行关键句。只在旁白讲“代理在做什么、说了什么”时使用。
- **代码骨架**：用彩色短横条代表代码行，不出现大段可读代码；旁白讲到具体条件或写法时，关键的一两行写成短伪代码（如 `类别 == "投诉"`）。
- **重画的界面样机**：文件管理器、设置卡、命令面板、手机外框等，按本规范的配色重新绘制、去掉细节。
- **暗色舞台上的浅色缩略图**：浅色页面线框或插画缩略图放在暗色舞台上，作为被比较、被生成、被检查的对象。前提是整体仍是示意结构（并排对照、表格、流程），浅色块只占局部。
- **过渡画面**：频道或主体介绍用的中心辐射图、章节路线图、“可跳过”的播放器示意。信息量低，但能维持全片风格统一。

### 不属于默认方案

- 实拍、照片、真实网站截图、真实软件录屏（有光标、长输出、滚动、系统外框）。
- 把旁白逐句搬到画面上，再加文字出现动画。
- 大标题、正文、装饰图标组成的常规演示文稿。
- 只更换标题和图标、反复套用同一个卡片版式。
- 与语义无关的粒子、炫光、镜头旋转和夸张转场。
- 将参考片中的具体品牌、产品名、人物照片固定套用到所有题材。

未来如需字幕，字幕应作为独立可选层；主体画面仍需独立完成解释任务。

## 3. 风格继承与内容重构

| 保持稳定的部分 | 随每份 SRT 重新设计的部分 |
|---|---|
| 暗色背景与低饱和层次 | 画面表达的主体与对象 |
| 圆角窗口、卡片、胶囊和简化线条 | 对象之间的因果、层级、比较和流转关系 |
| 固定的状态色含义（见 4.3） | 场景布局与数量 |
| 大面积留白与单一视觉焦点 | 动画如何表现变化 |
| 简洁、平稳、可追踪的运动 | 镜头长度与关键动作时间 |
| 少量必要文字 | 短标签、名称、数值 |

界面感是一种组织信息的设计语言，不意味着所有内容都必须发生在浏览器或终端里。学习、商业、科学、生活流程等题材，都可以用同样的形状、线条和颜色构建示意系统。参考片中已有跨题材的例子：用工资单演示测试（`v01-P`）、用组织关系图演示权限规则（`v01-Q`）、用人群沿路径减少演示用户流失（`v10-P`、`v13-AB`）。

## 4. 视觉系统

### 4.1 背景与层次

- 近黑背景作为舞台，全片统一。
- 窗口、卡片通过深灰色差、细边框和轻微阴影与背景分开。
- 优先形成一个清晰的主视觉区域，周围保留足够留白。
- 背景安静；当前动作的对象对比度最高，次要对象降暗。
- 不机械复制参考图中很小的文字；成片在实际观看尺寸下必须清楚可辨。

### 4.2 配色基准（暗色主题；亮色见 4.6）

前七项最初取样自参考视频解码画面；v2.1 在实际项目对比中发现原取样偏暗、画面发闷，窗口、卡片、骨架与次要文字各提亮了一档（下表为现行值，引擎 `assets/engine.html` 的 CSS 变量与之一致）。场景代码里只用变量，不要硬写这些色值。

| 用途 | 建议起点 | 使用方式 |
|---|---|---|
| 舞台背景 | `#0D0D0D` | 全片统一背景 |
| 窗口底色 | `#1D2025` | 主容器 |
| 标题栏底色 | `#181A1E` | 可选的窗口顶部结构 |
| 卡片底色 | `#2C3139`（次级 `#23272D`，描边 `#454B54`） | 内容模块与信息对象 |
| 主要骨架线条 | `#9AA2AD` | 较重要的抽象内容 |
| 次要骨架线条 | `#646C76` | 次级信息与细节 |
| 陶橙色 | `#D87756` | 当前操作、关键对象、代理、处理节点 |
| 清晰文本 | `#F2F2EE`（次要文字 `#AAB1BA`） | 必要标签 |
| 成功状态 | `#A6C985` | 已确认的完成或通过 |
| 错误状态 | `#DD6B80` | 错误或失败 |
| 警示状态 | 琥珀黄，建议从 `#E3B341` 起调 | 可疑、待确认、风险提示 |

多方对比的题材可以额外指定“阵营色”（例如 `v06` 全片固定橙 = A、紫 = B），第一个镜头就建立，贯穿到底，不与状态色混用。

### 4.3 状态语言（全片必须一致）

参考片在 15 支视频里反复使用同一套状态编码。新作品应在第一次出现时建立，之后不改含义。

| 视觉处理 | 含义 | 参考 |
|---|---|---|
| 橙色高亮 / 橙色描边 | 当前正在处理、当前讲到、代理本身 | `v01-U`、`v15-X` |
| 绿勾 / 绿点 | 已通过、已完成、已核实 | `v01-G` |
| 红叉 / 红点 / 红色状态词 | 失败、错误、被拦截 | `v01-I` |
| 黄色三角 | 可疑、遗漏、需要注意 | `v01-L`、`v06-AK` |
| 灰色 | 未检查、未激活、未知、未使用 | `v05-H`、`v07-BB` |
| 单独的灰色一栏 | “无法判断”，与成功、失败并列，不能画成成功 | `v05-K` |
| 橙色“放弃”状态 | 明确放弃、如实上报，区别于失败 | `v14-W` |
| 降暗 | 退出焦点、被遗忘、看不到 | `v01-N`、`v05-AC` |
| 50% 透明度（原「模糊」，2026-09 起不用模糊滤镜） | 尚未讲到、等待出场、想象不出来 | `v01-O2`、`v04-X` |
| 锁 | 顺序依赖未满足、无权访问 | `v01-K1`、`v11-S` |
| 虚线空槽 | 缺口、该有却没有 | `v03-B`、`v07-G` |
| 斜线填充 + 虚线参照 | 估算或推测值，区别于实测 | `v06-B` |
| 灰色占位块（如 `$▮▮.▮▮`） | 待揭晓的数值（金额、时长），先告诉观众要比什么；**概率不用这种写法** | `v06-AC` |
| 迷你圆环 +「概率」胶囊（`probChip`） | 有一个概率 / 把握，但旁白没给数值 | — |
| 暗橙色染色 | 意外改动、未兑现的部分 | `v08-A`、`v08-Y` |

状态变化必须配合形状或图标变化，不能只靠颜色。

### 4.4 组件库

参考片反复出现的组件如下。组件是词汇，不是模板；每次按语义挑选、组合、重新布局。

| 组件 | 形态 | 常用于 |
|---|---|---|
| 代理 / 执行者图标 | 橙色放射状图标，可带名称标签；**讲 Claude 时用 Claude 官方 logo**（`agent(p,{claude:1})`） | 主体、处理节点、正在工作的一方 |
| 人像 | 圆形头像轮廓；泛指的人（你 / 我 / 用户）只画头像、不写标签，具体角色（员工、经理、审批人）才带短标签 | 人工节点、审批、分工对比 |
| 卡片 | 圆角深灰块，内含标题 + 真实短标签 / 字段名（旁白没给具体值时，值可用短横条） | 任务、信息、对象、结果 |
| 胶囊 | 小圆角标签，可带图标或状态点 | 短语、参数、标签、状态词 |
| 窗口 | 带三色点标题栏的容器 | 一个系统、一个会话、一个产物 |
| 容器 + 容量条 / 百分比 | 固定大小窗口，边上一条随内容增长的条 | 上下文、额度、存储 |
| 进度轨道 | 横线上一串编号节点 | 分步构建、流程进度、时间 |
| 闸门 | 栅栏或升降杆图标，带状态灯 | 检查、放行、拦截 |
| 圆环 | 圆形轨道，节点分布在环上 | 循环、持续运行、反复检查 |
| 连线 | 直线、曲线、分叉线、Z 字线 | 关系、流向、分派、往返 |
| 计数器 / 大号数字 | 随动作滚动的数字 | 数量、成本、次数（必须来自旁白） |
| 仪表 / 柱 / 条 | 半圆仪表、竖柱、横条 | 质量、比较、成本、趋势 |
| 网格 / 点阵 / 方格阵 | 大量同质小块 | 规模、配额、合规率 |
| 矩阵表 | 行 × 列，格内有无点或勾 | 多方对比、逐项验收 |
| 计分板 | 固定位置的类别条 + 双方分数 | 贯穿全片的比较 |
| 风格化终端 | 暗色窗口 + 两三行短文字 | 代理说了什么、做了什么 |
| 代码骨架 | 彩色短横条排成的代码形状 | 代码质量、改动范围、纠缠 |

### 4.5 文字原则

文字用于命名与消除歧义：短名称、分类标签、必要数字、状态词。旁白的完整解释由对象和动作承担。

- 对话场景可以保留简短问题和回答，但不把整段解说塞进气泡。
- 需要表达“一句话的结构”时，可以把命令单独放大，只给关键部分上色或加下划线标签（`v02-R`、`v15-S`）。
- 需要表达“长”“啰嗦”“难读”时，用横条长度、滚动时长、无分段的块面表达，不写真实长文（`v05-L`、`v05-M`）。

### 4.6 亮色主题（Gumroad 官网风格）

与暗色共用第 4.3–4.5 节和第 5–8 节的全部规则（状态语言、组件、文字原则、揭示顺序、动作含义都不变），只换配色和容器样式。构建时 `--theme light`，引擎给舞台加 `.light`，CSS 变量整体切换。设计变量取自 gumroad.com 官方 CSS（与 yt-ppt 的 visual-style.md 一致）。

| 变量 | 亮色取值 | 用途 |
|---|---|---|
| `--bg` | `#F4F4F0` 米白 | 舞台底色；右下角黄色大圆 + 粉色小圆装饰（在内容下层，竖版移到右上角） |
| `--card` `--win` | `#FFFFFF` | 卡片、窗口 |
| `--card2` | `#E4E4DC` | 次级面板、棋盘深格等 |
| `--edge` | `#000000` | 所有描边：卡片 / 窗口 / 节点 / 胶囊 3px 纯黑 |
| `--l1` / `--l2` | `#242423` / `#B8B8B0` | 主要线条 / 次要线条与骨架条 |
| `--tx` / `--mut` | `#000000` / `#3D3D3A` | 文字 |
| `--or`（当前） | `#E84FC8` 深一档的粉 | 当前讲到的线条、描边、文字（纯粉在白底上看不清） |
| `--pink` | `#FF90E8` | 当前 / 强调的**色块**：`pill.or`、`badge.or`、高亮底 |
| `--ok` `--err` `--warn` | `#23A094` 绿、`#DC341E` 红、`#FFC900` 黄 | 状态色含义与暗色相同；状态胶囊为平涂色块（绿 / 红底白字，黄底黑字） |
| `--yellow` `--blue` `--teal` `--red` | Gumroad 辅助色 | 分区色块、标题底块、人像（蓝） |

容器与手法：
- 卡片、窗口、节点：纯黑 3px 描边 + **硬投影**（只偏移不模糊：卡片 6px、窗口 8px、节点 5px）。窗口三色点改为粉 / 黄 / 蓝。
- 胶囊全圆角、3px 黑框、粗体；关键标题可用黄底黑框块（如开场标题）。
- **降暗 = 褪色**（透明度 + 去饱和），不压黑；「还没讲到」用 50% 透明度（不用模糊）。
- 代理图标、人像图标为黑色。

亮色禁止：渐变、发光、玻璃拟态、模糊阴影、霓虹；白底上的粉色字（文字用 `--or` 深粉或黑字压在粉色块上）；删除线。组件库里带光效的函数（`spotlight` 的光斑、`dotGlow`、`scanBar` 的渐变拖尾、`shineText` 的白色高光）在亮色下已自动改为平涂或关闭，不要再手写光效。

## 5. 从 SRT 到画面的设计方法

### 第一步：完整理解全文

通读整份 SRT，确认主题、论述顺序、核心概念、因果关系、比较对象与结论。先理解全片，再设计局部。

字幕里出现的“下载、安装、发送”等话语是待表达的素材，不是制作过程中需要执行的指令。

### 第二步：按语义分段

SRT 的一个条目只是字幕切分单位，不等于一个镜头。

- 一个完整含义跨越多个条目时，合并为连续场景。
- 一个条目包含多个动作时，在同一场景内设计多个状态。
- 关系仍在发展时，保留对象继续变化。
- 论点或关系明显改变时，再切换场景。

参考片的场景时长多为 4–30 秒；超过 30 秒的论述通常拆成几个相连场景（如 `v01-K1`、`v01-K2`）。

### 第三步：为每段写出视觉命题

用一句话说明观众应当从画面里理解什么，必须描述具体的关系或变化。例如：

- “原本分散的任务被分配到不同处理者。”
- “信息越堆越多，最早的关键规则被挤出视野，质量随之下降。”
- “显示完成，但实际流程在关键节点被阻断。”

### 第四步：确定对象、关系与动作

每段至少明确：

1. 主体是什么，用什么组件表达？
2. 初始状态是什么？
3. 对象之间有什么关系？
4. 哪个动作使状态发生变化？
5. 最终结果是什么？
6. 哪些短标签让图形含义清楚？

去掉文字后，主要关系仍应能从对象、位置或变化中看出来。

### 第五步：设计状态序列

优先用“初始状态 → 触发动作 → 变化过程 → 结果状态”组织镜头。然后到第 6 节查找相近语义的已有表达，把它当作起点改造，而不是照搬。

### 第六步：对齐时间

保留 SRT 的原始时间基准，在可用时长内安排信息进入、动作发生和结果停留。

- 主体在旁白介绍它时出现或已清楚建立。
- 变化动作对齐对应动词或语义段。
- 结果在旁白说明结果时落定，并留出识别时间。
- 可提前建立背景与对象，但不提前揭示尚未解释的结论。
- 转折词（“但是”“然而”）是状态反转的最佳时机（`v11-T`）。
- 仅有 SRT 时按字幕时间与语义估计同步；没有逐词时间数据时，不宣称精确到词或音节。
- 不擅自重写旁白来适配动画，也不默认生成新配音。

## 6. 语义到画面的对照库

下表按语义分组，整理了参考片中反复出现、表达最清楚的做法。每行都是思路，不是固定镜头；具体设计须服从当次旁白。“参考”列的编号可在 `library.md` 中查到完整描述。

### 6.1 数量、规模与增长

| 旁白含义 | 画面 | 关键动画 | 参考 |
|---|---|---|---|
| 工作量巨大 | 满屏同质小块组成网格，中央一张计数卡 | 小块随机亮起，计数从 0 滚到旁白给出的数字 | `v01-A` |
| 数量很多 | 列表快速填满，或卡片持续增加并自动重排 | 逐批加入，角标计数递增 | `v06-W`、`v11-A` |
| 海量中有一个不同 | 传送带式同质队列 + 一个异类 | 队列持续滚动，异类局部放大 | `v03-H` |
| 递增的复杂度 | 编号柱状图，柱顶用尺码标签（XS…XL） | 柱子从左到右逐根升起 | `v01-K1` |
| 倍数关系 | 等高分段堆叠的柱 | 段数本身就能读出倍数 | `v06-AE` |

### 6.16 真实性约束

- 象征性数量不要伪装成数据。旁白说“效率提升”，可以展示等待减少；没有依据时不添加“提升 300%”。
- 计数器、比分、价格只使用旁白给出的数值；没有具体数值时用尺码标签、条长对比或占位块。
- “被拦截”这类预期内的结果，如果是测试通过，用绿勾表示测试通过（`v01-Q`），不要误画成失败。
- 不把未知画成成功（用 6.4 的三态），不把相关画成因果，不把减少画成完全消失。

## 7. 动画设计原则

### 7.1 动作承载含义

| 动作 | 含义 | 注意 |
|---|---|---|
| 出现 | 创建、加入、开始被关注 | 按意义顺序逐个出现，不齐飞 |
| 连线生长 | 建立关系、传递、分派 | 从源头向目标画，方向即因果方向 |
| 移动 / 平移 | 传递、分配、归类、委托 | 迁移要在原处留空槽，复制要保留原件 |
| 飞入 / 吸入 | 汇总、被采纳、写入 | 从来源处飞来，让观众知道内容从哪来 |
| 合并 | 汇总、去重、统一 | 用上下文区分含义 |
| 拆分 / 切割 | 分解任务、划分类别 | 橙色切割线比直接散开更清楚 |
| 尺寸变化 | 数量、体量或重要性变化 | 须有清楚参照 |
| 颜色与标记变化 | 状态改变 | 配合形状或图标，遵守 4.3 |
| 降暗 | 退出焦点、被遗忘、看不到 | 被遗忘的规则“逐渐变暗”，不是突然消失 |
| 淡出 | 退出当前过程 | 表示删除时需有依据 |
| 掉落 | 被丢弃、遗漏 | 比淡出更能表达“遗漏” |
| 向后叠放 | 被推翻但留下痕迹 | 叠层厚度 = 次数 |
| 半透明（50%）↔ 不透明 | 未提及 / 讲到；想象不出 / 终于明白 | 列举时未讲到的项先半透明占位；不用模糊滤镜 |
| 原地替换 | 同一对象被改写、脱敏、换名 | 位置不变，只换内容 |
| 弹回 | 被拒绝、不能越过 | 用于闸门拦截 |
| 沿环绕行 | 循环、持续运行 | 每圈留下可见的累积 |
| 扫描线 / 逐行高亮 | 正在读取、检查、处理 | 扫描长度可对应成本 |

同一动作不要被赋予与内容不一致的含义。

### 7.2 让观众追踪同一个对象

- 同一对象在连续状态中保留形状、颜色或位置线索；新状态从旧状态发展出来。
- 需要跨场景追踪的对象，给它一种固定颜色，每次出现都用同色（`v02-W` 的敏感值）。
- 需要比较时，用**同构前后对照**：两段构图完全相同，只改一处（`v07-AY`、`v07-BH`）。
- 需要证明“没受影响”时，让那个对象**刻意保持静止**（`v02-K`、`v08-K`、`v12-Q`）。
- 内容需要切换时可以干净切场，不必强行变形连接。

### 7.3 揭示的顺序

- 先建立理解所需的对象，再演示关系，最后呈现结果。
- 列举多项时，先把全部项以 50% 透明度占位，讲到哪项哪项恢复不透明，讲解某项时其余降暗（`v01-O2`、`v15-U1`）。
- 需要让观众知道“要比什么”但暂不给答案时，先用灰色占位块写出格式（`v06-AC`）。
- 对比结果时，两方先后揭晓，不同时揭晓（`v06-D`）。
- 表达“被掩盖”时，先显示真相，再被覆盖（`v14-J`）。
- 表达“删除”时，要让观众看见删除动作本身（`v14-K`）。
- 人工决定有两种结果时，两种结果都要演示（`v10-K`）。

### 7.4 节奏与注意力

- 同一时刻只有一个主要动作焦点，次要内容降低对比度。
- 结果需要可读的停留，不为持续运动而破坏理解。
- 默认平稳、克制的缓入缓出，少用夸张弹跳。
- 转场以干净切换和淡入淡出为主；不使用旋转、缩放冲击等夸张转场。

以下是从参考片观察到的制作起点，并非恢复出的原始曲线或全片统一参数：

| 动作 | 观察到的时长 |
|---|---|
| 局部显现、轻微状态切换 | 约 0.15–0.35 秒 |
| 列表逐行加入 | 约 0.2 秒一行 |
| 同组元素逐项出现 | 约 0.1–0.3 秒间隔 |
| 检查项逐项打勾 | 约 0.5 秒一项 |
| 卡片归类、移动、组合 | 约 0.4–0.8 秒 |
| 组件微交互（悬停 → 按下 → 加载 → 完成） | 每态约 0.5–1 秒 |
| 计数从 0 滚到目标值 | 数秒，与画面变化同步 |
| 结果停留 | 至少约 1 秒，重要结论更长 |
| 完整处理过程 | 按旁白分配，必要时持续数秒 |

时长最终服从理解与旁白节奏，不为套用参数改变语义。

### 7.5 全片层面的结构手法

- **贯穿元素**：比较类题材可以用一块固定位置的计分板串起全片，每个章节结束更新一次，片尾整体退出、换上汇总表（`v06-S`、`v06-AM`）。
- **章节路线图**：全部章节先半透明占位，当前章节不透明、编号变色；已完成章节保持完成色（`v12-R`、`v12-AG`）。
- **预告清单**：先给出完整清单建立预期，再让清单降暗、主角卡浮到前景，表示“先插入一段别的内容”（`v08-D`）。
- **可跳过提示**：带章节刻度的播放器，播放头弧线越过一段（`v04-K`、`v09-D`）。

## 8. 跨题材示例

### 示例 A：信息整理

旁白：“这些信息里有很多重复内容，整理后只需要保留关键部分。”

画面：数张带有重复标记的信息卡进入处理区域，相同条目逐渐重合，多余副本退出，最后留下少量清晰卡片。

设计重点：让“重复”和“保留”可见，不只是把一张大卡片变小。可参考 `v12-S`：让被丢掉的部分留在原地变暗，观众能看见丢了什么。

### 示例 B：学习方法

旁白：“把零散知识建立联系，才能形成自己的知识体系。”

画面：分散节点先呈现孤立状态，相关节点之间逐步连线，再聚合为几个相互关联的模块。

设计重点：用连接关系的建立表达理解深化（参考 `v10-AK` 的聚拢成群）。

### 示例 C：任务分工

旁白：“任务拆给不同成员，再把结果汇总。”

画面：一张主任务卡被橙色切割线分成三块，分别沿分支进入处理节点；各自完成后，结果沿路径飞入同一个成果面板。

设计重点：拆分、处理、汇总三个动作分别对应旁白进展（参考 `v01-K1`、`v01-S1`）。

### 示例 D：流程失效

旁白：“显示完成，不代表实际使用时就能成功。”

画面：任务面板显示完成标记，随后一个测试对象进入实际流程，在关键节点被闸门拦住，闸门灯变红，节点标出错误。

设计重点：通过状态与实际结果的差异表达观点（参考 `v05-C`、`v01-I`）。

### 示例 E：习惯养成（非技术题材）

旁白：“一开始每天都坚持，过了两周就慢慢断了。”

画面：一排日历方格沿时间轴排开，前面的格子逐个打勾；到第三周，勾之间开始出现空格，空格越来越多，最后一整行变灰，状态标签由绿色“坚持中”变为灰色“已停止”。

设计重点：借用“停止付费”（`v10-R`）和“流失”（`v10-P`）的手法，把“断掉”画成可见的空缺累积。

### 示例 F：两种方案比较（非技术题材）

旁白：“两家装修公司报价差不多，但一家把材料费算在外面。”

画面：两张同构报价卡并排，总价条长度接近；随后其中一张卡下方展开一行虚框“材料费”，虚框逐渐填实，总价条随之变长。

设计重点：用“同构对照 + 只改一处”（`v07-AY`）和“差额用虚框补上”（`v06-AD`）表达隐藏成本。

## 10. 设计交付应包含的内容

具体文件格式和实现技术可以另行决定，但完整设计至少覆盖：

1. **全文理解与语义分段**：说明每段在整篇中的作用，覆盖所有有效内容。
2. **本片视觉规则**：对象、必要标签、状态色含义（沿用 4.3）、阵营色（如有）、构图尺度、贯穿元素（如有）。
3. **逐场景分镜**：画面表达什么、对象如何组织、如何变化，并注明借鉴的参考段落。
4. **动作时间表**：出现、移动、状态切换和结果停留的时间。
5. **关键画面预览**：至少能检查初始状态、关键变化和结果状态。
6. **连续性与同步检查**：镜头衔接、对象一致性和旁白对应关系。

每个场景记录：

| 字段 | 内容 |
|---|---|
| 场景编号与时间范围 | 对应原始 SRT 的起止时间 |
| 对应旁白与条目 | 保留语义依据，避免漏句或错配 |
| 视觉命题 | 观众应该理解的关系或变化 |
| 对象与短标签 | 各形状代表什么 |
| 构图 | 对象位置、层级、路径、分区 |
| 状态序列 | 初始 → 触发 → 过程 → 结果 |
| 动画与时间 | 各动作何时开始、何时结束 |
| 借鉴 | 参考了第 6 节或素材库中的哪一段，改动了什么 |
| 场景衔接 | 哪些对象延续，如何进入下一段 |
| 验收要点 | 哪个可见变化证明这段表达成功 |

每个镜头都应有可执行描述。例如“重复卡片在中央处理区重合，多余副本淡出，保留项向右进入结果区”，比“展示信息精简的高级科技动画”更具体。

## 11. 验收标准

### 内容对应

- [ ] 完整覆盖 SRT 中需要表达的内容，没有只做开头或精彩片段。
- [ ] 每段画面对应本段旁白的实际含义。
- [ ] 对象身份、因果、先后与分类关系正确。
- [ ] 没有把未知画成成功、把相关画成因果、把减少画成完全消失。
- [ ] 没有虚构数值、界面能力或旁白没有支持的结果。

### 视觉表达

- [ ] 画面呈现了事情发生的过程，主要信息不是靠阅读旁白文字获得。
- [ ] 图形身份清楚，必要标签简短。
- [ ] 主要关系能从对象、位置或变化中辨认。
- [ ] 状态色含义全片一致，并配合形状或图标变化。
- [ ] 视觉风格符合第 9 节参考图，构图服务于当前内容。
- [ ] 全片存在符合内容的布局变化，没有机械套版。
- [ ] 无需引入实拍、真实截图或录屏来完成表达。

### 动画与时间

- [ ] 动作具有语义作用，能说明为何移动、合并、降暗或掉落。
- [ ] 关键动作与对应旁白段落同步；转折对齐转折词。
- [ ] 观众能追踪对象从初始状态到结果状态的变化。
- [ ] “没受影响”用静止证明，“删除”让观众看见删除过程。
- [ ] 主要动作不过度竞争注意力，结果有足够识别时间。
- [ ] 场景连接清晰，无无意跳变、闪帧或对象突失。

### 可读性

- [ ] 暗色环境下主对象、状态和标签仍清楚可辨。
- [ ] 在实际成片比例与观看尺寸下检查过布局和文字。
- [ ] 没有将抽帧联系表本身误当成成片布局。
- [ ] 露出文字时观众能读懂每个对象是什么：旁白讲到的具体对象都有真实短标签；没有成片的灰色骨架条、空胶囊、空格子、无标签图标充当内容。骨架条只表示「一大段文字 / 数量多」，且第一行是真实短句。
- [ ] 半透明占位只用于还没讲到的内容；场景结尾时讲过的东西都已恢复不透明。
- [ ] 泛指的人像（你 / 我 / 用户）没有文字标签；成组标签整组居中、边缘角标不压卡内元素、连线没有两个以上折角、没有单字孤行、概率没有写成 ▮▮%。
- [ ] 主体文字 ≥26px、常驻导航 ≥22px；结尾帧主体占安全区宽 ≥75%、高 ≥60%，中途步骤也不空半屏（`scripts/audit.py` 可量）。

如果一段旁白只是被转成一张文字卡，即使颜色与参考一致，也不能视为满足本需求。反过来，如果图形关系对了、但对象全是灰条和空框、观众读不出在讲什么，同样不合格。

## 12. 供编写 skill 时保留的总要求

**输入可以变化，视觉语言保持统一，画面设计必须随语义重新生成。**

系统应当像一位理解旁白的动态图形设计师：先判断这段话要解释什么，到第 6 节和素材库里找到最能让观众看懂的对象、关系和动作，以暗色示意风格重新设计，并按照 SRT 时间组织动画。

本需求不限定渲染框架、生成模型或固定模板数量，也不要求复制参考片的全部视觉类型。后续实现选择服务于上述设计目标。
