# scenes.json 场景数据格式

一个项目一份 `项目/schematic/scenes.json`，横版、竖版共用。分镜审阅页和成片网页都从它读取。

```json
{
  "title": "片名或主题",
  "rules": {
    "主体": "Claude = 官方 logo；其他代理 = 橙色放射图标；人 = 蓝灰头像；……",
    "状态色": "橙 = 正在处理；绿 = 通过；红 = 被拦截；灰 = 未处理",
    "贯穿元素": "（可选）全片反复出现的对象，如闸门、计分板",
    "阵营色": "（可选）多方对比时各方的固定颜色"
  },
  "scenes": [
    {
      "id": "s01",
      "name": "三百个屏幕的重建",
      "a": 1, "b": 7,
      "prop": "这是一项巨大的工程：数百个屏幕被 AI 代理逐个重建",
      "objects": [
        {"name": "屏幕网格", "shape": "满屏深灰小卡，约 12×6", "label": ""},
        {"name": "计数卡", "shape": "中央卡片，大号数字", "label": "已重建"}
      ],
      "layout": "网格铺满舞台，计数卡居中压在网格上",
      "sequence": [
        {"at": 1, "phase": "初始", "do": "单个手机线框出现"},
        {"at": 5, "phase": "触发", "do": "拉远：手机缩成网格里的一格，满屏网格淡入"},
        {"at": 6, "phase": "过程", "do": "格子随机点亮，计数从 0 滚动"},
        {"at": 7, "phase": "结果", "do": "计数停在 300"}
      ],
      "refs": ["v01-A 网格 + 实时计数", "规范 6.1"],
      "carry": "代理图标保留到下一场景",
      "accept": "观众看到数量从 0 增长到旁白所说的 300"
    }
  ]
}
```

## 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 场景编号，建议 `s01`、`s02`…；scenes.js 用它作键 |
| `name` | 是 | 场景短名（给人看） |
| `a` / `b` | 是 | 本场景覆盖的字幕序号范围（含两端）。全部场景必须按顺序、不重不漏地覆盖所有字幕 |
| `prop` | 是 | 视觉命题：一句话写出观众应理解的**关系或变化**，不能写“科技感画面” |
| `objects` | 建议 | 对象清单：名字、用什么组件表达、必要的短标签 |
| `layout` | 建议 | 构图：位置、层级、路径、分区 |
| `sequence` | 是 | 状态序列。`at` = 这一步对齐的字幕序号（必须在 a–b 之间）；`dt` = 可选的句内偏移秒数（一句字幕里有几个动作时用，如 `{"at":10,"dt":1.5}`）；`phase` = 初始 / 触发 / 过程 / 结果；`do` = 可执行的画面描述 |
| `refs` | 建议 | 借鉴来源：规范章节号或素材库编号（如 `v01-I`），并说明借的是什么 |
| `carry` | 可选 | 场景衔接：哪些对象延续到下一场景 |
| `accept` | 建议 | 验收要点：哪个可见变化证明这段表达成功 |

## 划分场景的要点

- 字幕条目只是切分单位。一个完整含义跨多条字幕就合成一个场景；论点或关系明显改变才切换。
- 常见时长 4–30 秒。短于 3 秒或长于 30 秒，脚本会提醒，确认是否合并或拆分。
- `sequence` 的 `at` 决定动作时间；成片代码里用 `S(at)` 取这句字幕的开始时间，动作会自动提前 0.2 秒启动。
- 一个场景只有一两句字幕时，状态序列的几步用 `dt` 错开，否则分步截图和分镜审阅页分不出先后。
- 写动画时如果改了设计（换了手法、调了顺序），**同步改回 scenes.json**，保证分镜审阅页和成片一致。
- 需要跨场景连续演变的画面（同一组对象持续变化），在 scenes.js 里用 `span` 让一个构建覆盖多个场景，而不是硬切。
