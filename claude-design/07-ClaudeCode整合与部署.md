# 07 · 交接 Claude Code ＋ 部署 Netlify

> 对应视频章节：6/7 交接ClaudeCode

Claude Design 做的是原型，导出的文件在浏览器里跑不起来（那是它自己的画布格式）。真正要上线，要交给 Claude Code **翻译成真代码**。

## 第一步：收集五段交接 prompt

每个作品：右上角 **Share** → **More formats and apps** → 下面 **Your destinations** 区块 → **Claude Code** 旁的 **Send** → 选本机 Claude Code → 复制它给的交接 prompt。

依序做五次：**设计系统 → 网站 → 广告制作台 → PPT → 合同**，一个都不能少。

**设计系统第一个送有讲究**——它是根基，颜色、字体、组件都在里面，Claude Code 先看到它，后面四样的代码才知道该引用哪套样式。

## ⚠️ 关键：五段一起送，不要送一段跑一段

先把五段 prompt 全部收集到一个文本文件。为什么不一段一段跑？**跑网站的时候它不知道后面还有广告、PPT、合同**，可能把网站建成独立项目，目录结构从一开始就错了。**它需要一开始就看到全貌，才能设计出对的结构。**

## 第二步：整合总指令

打开新的 Claude Code session，**五段一次性贴上**，接这段总指令：

```
我刚才给你的这些东西：设计系统、网站、合同、广告制作台、PPT，
请把它们整理成一个统一的项目仓库。

这个仓库要包含：
1. 网站，而且要能直接部署到Netlify
2. 内部工具，做成skill的形式，让我可以直接叫你帮我生合同、生广告、生PPT

请先给我一个计划。
```

它会先给计划：设计系统单独一个目录、网站一个目录、三个 skill（生合同、生广告、生PPT）。关键的一句话：**两条线唯一的耦合点是设计系统**——网站从这里取色取字，skill 生出来的合同、PPT 也从这里取。改一次颜色，全部跟着变。

跑完后注意两件事：

1. **它做的不是复制，是翻译**——表单验证、导航下拉、广告动画全部重写成原生 JavaScript，但设计系统的 token 原封不动搬过来，所以品牌一模一样。
2. **它抓到一个隐形 bug**：网站上的两个估价表单其实是 JS 动态生成的空 div，而 **Netlify 是部署时扫描 HTML 来发现表单的，不会执行 JavaScript**。不修的话，浏览器里一切正常、客户填完显示成功——但单子全丢，且没有任何错误提示。它在 HTML 里加了一个隐藏的静态表单去注册。
3. 它还写了 **CLAUDE.md**——给 Claude Code 看的说明书。以后说「帮我生一份给王先生的合同」，它就知道去哪拿模板、怎么填。

## 第三步：部署 Netlify

先看配置——`netlify.toml` 里的重点是 `publish = "site"`：网站在 site 子目录里，根目录放的是不该被发布的东西（脚本、素材）。

```bash
npx netlify-cli deploy --dir=site --prod
```

- `npx`：不用安装，临时下载跑完就算
- `--dir`：要传哪个文件夹
- `--prod`：直接发布到正式环境（不加只是预览版）
- 第一次跑会叫你登录 Netlify、选 team、给网站取名

## 第四步：开启收单（Netlify Forms）

⚠️ **Netlify 的表单功能默认是关的**：

1. Netlify 后台 → 项目 → **Forms** 分页 → 点 **Enable form detection**
2. **开完必须重新部署一次**：

```bash
npx netlify-cli deploy --dir=site --prod
```

为什么？Netlify 是在**部署时**扫描 HTML 找表单的——你开启检测之前的那次部署它根本没看。

3. 回 Forms 页面刷新，`estimate` 表单出现（提交数 0）
4. 打开线上网址填一笔测试单 → 送出 → 回 Forms 刷新 → 单进来了，姓名电话 email 全在

从一段公司简介，到一个真的能收到客户单子的网站——整条链，通了。
